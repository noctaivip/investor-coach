# Investor Coach — Production PWA + AI Investor

Готовое русскоязычное PWA-приложение для тренировки предпринимателя перед общением с инвесторами. Базовое обучение и offline-режим работают локально. Для production AI-инвестора в проект включён отдельный безопасный serverless backend в папке `backend/`: OpenAI API key никогда не попадает в публичный GitHub Pages код.

## 1. Как установить зависимости

Фронтенд/PWA не имеет сторонних runtime-зависимостей и собирается как статический HTML/CSS/JS. Для production AI-backend используется Cloudflare Worker; для его развёртывания нужен Node.js/npm и `wrangler` (описано в `backend/README.md`).

Для локального запуска фронтенда нужен любой простой HTTP-сервер. Например, если установлен Python 3, дополнительных пакетов для фронтенда не требуется.

## 2. Как запустить локально

Из корня проекта выполните:

```bash
python3 -m http.server 8080
```

После этого откройте:

```text
http://localhost:8080
```

Service Worker и PWA разрешены на `localhost`. Не открывайте `index.html` напрямую через `file://` — Service Worker в этом режиме не работает.

## 3. Как собрать production-версию

Для фронтенда отдельная сборка не требуется: проект состоит из статических HTML/CSS/JS-файлов. AI-backend разворачивается отдельно командой `npm run deploy` из папки `backend/`.

Для публикации нужны:

```text
index.html
styles.css
data.js
app.js
manifest.json
sw.js
icons/
```

Перед новой публикацией рекомендуется изменить `APP_VERSION` в `sw.js`, например `2.0.0` → `2.0.1`. Это создаст новый cache namespace и удалит старые PWA-кэши после активации новой версии. Даже без изменения номера версии приложение при наличии сети использует network-first стратегию и обновляет локальный кэш свежими файлами.

## 4. Как загрузить проект на GitHub

1. Создайте новый репозиторий на GitHub.
2. Загрузите содержимое этой папки в корень репозитория.
3. В GitHub откройте `Settings → Pages`.
4. В `Build and deployment` выберите публикацию из нужной ветки, обычно `main`, и папку `/ (root)`.
5. Сохраните настройки и дождитесь публикации GitHub Pages.

После следующих изменений: обновите код, при релизе увеличьте `APP_VERSION` в `sw.js`, сделайте commit и push. После обновления сайта установленная PWA при следующем запуске с интернетом проверит Service Worker и основные ресурсы, активирует новую версию и обновит кэш.

## 5. Как разместить проект на своём сайте

Разместите все файлы проекта в одной публичной папке сайта, сохранив относительную структуру, например:

```text
https://example.com/investor-coach/
```

Сайт должен работать по HTTPS. `manifest.json`, `sw.js`, `index.html` и папка `icons` должны быть доступны из той же директории приложения. Service Worker зарегистрирован с относительным путём и контролирует текущую директорию PWA.

Если приложение публикуется в корне домена, используйте:

```text
https://example.com/
```

Если основной сайт находится отдельно, можно разместить PWA в подпапке и добавить на основной сайт ссылку или кнопку на URL этой подпапки.

## 6. Как установить PWA на Android

1. Откройте опубликованный HTTPS-сайт в Chrome или другом поддерживающем PWA браузере.
2. В приложении нажмите **«Установить приложение»**.
3. Подтвердите системный запрос установки.
4. После установки приложение будет запускаться с домашнего экрана в режиме `standalone`, без обычной браузерной панели.

Если браузер не предоставляет автоматический install prompt, кнопка покажет инструкцию; также можно открыть меню браузера и выбрать **«Установить приложение»** или **«Добавить на главный экран»**.

## 7. Как установить PWA на iPhone / iPad

1. Откройте опубликованный HTTPS-сайт в Safari.
2. Нажмите **«Установить приложение»** внутри интерфейса — откроется краткая инструкция.
3. В Safari нажмите **«Поделиться»**.
4. Выберите **«На экран „Домой“»**.
5. Подтвердите добавление.

На iOS Safari не предоставляет такой же автоматический `beforeinstallprompt`, как Chrome на Android, поэтому используется стандартный механизм **«Поделиться → На экран „Домой“»**.

## PWA и обновления

- Manifest: `manifest.json`.
- Service Worker: `sw.js`.
- Режим запуска: `standalone`.
- Иконки: 192×192, 512×512 и maskable 512×512.
- Основные ресурсы предварительно кэшируются для offline-работы.
- Навигация и локальные ресурсы используют network-first: при наличии сети берётся актуальная опубликованная версия и обновляется runtime cache; без сети используется сохранённая копия.
- При выпуске новой версии измените `APP_VERSION` в `sw.js`. Новый Service Worker активируется через `skipWaiting`, старые cache namespaces удаляются, а открытое приложение перезагружается под новым контроллером.
- Пользовательский прогресс хранится отдельно в `localStorage` и не очищается при обновлении Service Worker.

## Что сохранено из исходного MVP

Карта знаний, тесты, слабые термины, Speak-тренировка, Pitch Trainer, симуляция разговора с инвестором, 30-дневная программа, метрики и сохранение прогресса работают локально как и раньше. Интерфейс и учебные объяснения локализованы на русский язык; международные инвестиционные термины и аббревиатуры (`CAC`, `LTV`, `ARR`, `SAFE`, `Term Sheet` и т. п.) сохранены как профессиональная терминология.


## Учебная логика версии 4.0

- Active recall: определение скрыто до самопроверки.
- Интервальные повторения: 0 / 1 / 3 / 7 / 14 / 30 / 60 дней в зависимости от успешности.
- Ошибочные темы возвращаются раньше и получают повышенный приоритет в тестах.
- Два трека: ускоренный 7-дневный интенсив и системный 30-дневный курс.
- Голосовой режим для объяснения терминов, pitch и симулятора инвестора. Распознанная речь накапливается и отправляется только после кнопки «Отправить».
- Голосовая функция использует Web Speech API браузера и требует разрешения на микрофон; доступность распознавания зависит от браузера/ОС.
- На мобильном экране используется нижняя навигация из пяти основных разделов.

После публикации версии на GitHub Service Worker `4.0.0` запрашивает свежие файлы и заменяет старый кэш.


## Production AI Investor v5

1. Сайт/PWA остаётся на GitHub Pages.
2. AI backend разворачивается отдельно из `backend/` как Cloudflare Worker.
3. В Worker задаётся секрет `OPENAI_API_KEY`; ключ **не хранится во фронтенде**.
4. Голосовой AI-режим использует `MediaRecorder`: аудио остаётся на устройстве во время речи и отправляется только после кнопки **«Отправить»**.
5. Backend транскрибирует аудио и передаёт текст AI-инвестору через OpenAI Responses API.
6. AI оценивает смысл, цифры, unit economics, GTM, рынок, риски, противоречия и формирует следующий диагностический вопрос.
7. Накопительная память проекта и слабые темы сохраняются локально и используются для адаптации следующих сессий.
8. Если backend недоступен, приложение автоматически возвращается к локальным тестам/эвристикам, поэтому базовый курс не ломается.

### Важно

GitHub Pages — статический хостинг и не может безопасно выполнять секретные AI-запросы. Поэтому для реального production AI требуется один раз развернуть `backend` и указать его HTTPS URL. Это архитектурное требование безопасности, а не ограничение интерфейса.

## Версия 6: установка и ускоренный коуч

На главной странице есть заметная кнопка **«Скачать приложение»**. На Android она вызывает стандартный PWA install prompt, когда браузер его предоставляет. На iPhone/iPad открывается инструкция **Safari → Поделиться → На экран «Домой»**. После установки приложение показывает состояние «Приложение установлено».

В разделе **«Курс»** и на главной доступен **ускоренный коуч** на 1, 3 или 6 часов. Он чередует 20-минутные блоки active recall, новых терминов, голосового объяснения, AI-инвестора, pitch и смешанной проверки с 5-минутным восстановлением. Сессия хранится в `localStorage`, поэтому таймер корректно восстанавливается после перезапуска PWA. На поддерживаемых браузерах используется Screen Wake Lock; голосовые подсказки можно отключить.
